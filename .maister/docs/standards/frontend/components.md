## Components and Structure

### Organised by Feature, Not by Layer

`src/` holds feature folders (`offer/`, `inventory/`, `user/`, `layout/`, `config/`, `order/`), each
with `components/`, `hooks/` and `helpers/` as needed, plus a flat `{feature}.api.ts` and, where
useful, `{feature}.types.ts` at its root. Shared primitives live in `core/`, routes in `routes/`.
There is no global `components/`, `utils/` or `services/` folder, and adding one would be a
regression.

### PascalCase Features, kebab-case Primitives

Feature components are one per file, `PascalCase.tsx`, named after the component they export. The
shadcn and Radix primitives under `core/ui/` keep their upstream kebab-case file names and export
lowercase-named building blocks composed with the `cn()` merger defined in `core/ui/utils.ts`.

### Props Inline, Destructured, Alphabetical

A component takes one destructured props object whose type is written inline at the signature, with
keys in alphabetical order. A separate named `Props` type appears only when the shape is imported
elsewhere. `React.FC` is not used.

```tsx
export function BreakdownList({
  breakdown,
}: {
  breakdown: OfferOutput["breakdown"] | undefined
}) { ... }
```

### Forms: React Hook Form, Shared by Context

The offer form is created once in `OfferFormProvider` and reached deeper in the tree with
`useFormContext<WallOfferInput>()`. Native inputs use `register`, everything Radix-backed uses
`<Controller>`, repeated sections use `useFieldArray`, and scoped subscriptions use `useWatch`.
Validation rules are declared inline with Polish messages; there is no Valibot resolver in the form
layer.

### Routes Export `Route`, Component Below

Each file in `src/routes/` exports `const Route = createFileRoute("<path>")({ ... })` at the top and
declares its component below, or imports it. Auth redirects live in the route `loader`, branching on
`error instanceof ApiError && error.status === 401`. `routeTree.gen.ts` is generated by TanStack
Router and is never edited by hand.

### The Browser Bundle Does Not Import Domain Code

The domain package is backend-only: importing it into the web app ships domain logic in the browser
bundle. Calculations are reached through API endpoints.

**Known deviation, to be repaid.** Eleven files under `packages/apps/web/src` currently import
runtime values from `@/domain/models/*` (`COMPONENT_CATEGORIES`, `CATEGORY_REQUIREMENTS`,
`DEFAULT_SHELF_COUNT_BY_HEIGHT`, `layoutConstraints`). The fix is to move shared constants into
`packages/schemas`, which is explicitly the shared package. Do not add new imports of this kind.

### Single Responsibility, Minimal Props

A component renders one thing. State stays local until something else genuinely needs it, and props
carry what the component cannot derive.
